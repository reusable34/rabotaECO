# Руководство по применению изменений

## Выполненные изменения

### Backend

1. **Расширена модель Requirement** - добавлены поля:
   - `basis` - основание (КоАП статья)
   - `artifacts` - артефакты (JSON массив)
   - `document_year` - год документа
   - `responsible_person` - ответственный (ФИО)

2. **Созданы миграции**:
   - `m240101_000010_add_requirement_fields.php` - добавляет новые поля в requirements
   - `m240101_000011_add_responsible_person_to_clients.php` - добавляет поле ответственного в clients

3. **Доработан RequirementGeneratorService**:
   - Использует полную матрицу требований из критериев
   - Добавляет основания (КоАП статьи) для каждого требования
   - Добавляет артефакты для каждого требования
   - Правильно рассчитывает дедлайны

4. **Добавлен метод пересчета требований** в RequirementController:
   - `POST /requirement/recalculate` - пересчитывает требования на основе параметров клиента

5. **Обновлена модель Client** - добавлено поле `responsible_person`

### Frontend

1. **Обновлены типы TypeScript** - добавлены новые поля в интерфейсы Requirement и Client

2. **Полностью переделана страница требований** (`/requirements`):
   - Таблица с колонками: Требования, Основание, Артефакты, Год документа, Статусы, Срок выполнения, Ответственный
   - Фильтры: категория НВОС, водопользование, побочный продукт, ответственный
   - Кнопка "Пересчитать требования"
   - Вкладки для навигации (как на скриншотах)
   - Стилизация согласно дизайну

## Шаги для применения изменений

### 1. Применить миграции базы данных

```bash
cd backend
php yii migrate
```

Это применит две новые миграции:
- Добавление полей в таблицу requirements
- Добавление поля responsible_person в таблицу clients

### 2. Пересоздать требования для существующих клиентов (опционально)

Если у вас уже есть клиенты в базе, вы можете пересоздать для них требования с новыми полями:

```bash
# В консоли Yii2 или через API
# Для каждого клиента вызвать метод пересчета требований
```

Или через API:
```bash
POST /requirement/recalculate
{
  "category_id": 3,
  "has_well": false,
  "has_river": false,
  "has_byproduct": false,
  "responsible_person": "Иванов Иван Иванович"
}
```

### 3. Перезапустить backend (если используется)

```bash
# Если используется Docker
docker-compose restart backend

# Или просто перезапустить PHP-FPM/Nginx
```

### 4. Перезапустить frontend

```bash
cd frontend
npm run dev
# или
npm run build && npm start
```

## Проверка работы

1. Войдите в систему
2. Перейдите на страницу `/requirements`
3. Проверьте:
   - Отображается таблица требований с всеми колонками
   - Работают фильтры
   - Кнопка "Пересчитать требования" работает
   - Требования отображаются с основаниями и артефактами

## Структура данных требований

Каждое требование теперь содержит:
- **title** - название требования
- **basis** - основание (например, "КоАП РФ 8.21 ч.1")
- **artifacts** - массив артефактов (например, ["Проект ПДВ/НДВ", "Разрешение/КЭР"])
- **document_year** - год документа (по умолчанию текущий год)
- **deadline** - срок выполнения
- **status** - статус (pending, in_progress, completed, not_completed)
- **responsible_person** - ответственный (ФИО)

## Примечания

- Все требования генерируются автоматически на основе категории НВОС клиента
- Дополнительные требования добавляются при наличии скважины, реки или побочного продукта
- Матрица требований соответствует файлу `Критерии_для_формирования_требований_.md`
