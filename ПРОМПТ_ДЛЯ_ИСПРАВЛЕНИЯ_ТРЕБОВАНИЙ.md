# ПРОМПТ ДЛЯ ИСПРАВЛЕНИЯ ГЕНЕРАЦИИ ТРЕБОВАНИЙ

## Проблема

В системе генерации требований для III категории НВОС не создаются некоторые обязательные требования. 

**Текущая ситуация:**
- Для III категории должно быть 16 базовых требований: `[1, 2, 3, 4, 5, 6, 8, 9, 10, 14, 15, 16, 17, 18, 21, 22]`
- Но создаются только 12 требований (отсутствуют ID: 14, 15, 16, 17, 18)
- Также не создаются дополнительные требования:
  - Лицензия на недра (если есть скважина)
  - Технические условия (если есть побочный продукт)

## Что должно быть

По файлу `Критерии_для_формирования_требований_.md`:

**Для III категории:**
- 16 базовых требований: `[1, 2, 3, 4, 5, 6, 8, 9, 10, 14, 15, 16, 17, 18, 21, 22]`
- + Лицензия на недра (если `has_well = true`)
- + Технические условия (если `has_byproduct = true`)

**Для других категорий:**
- I категория: 18 требований `[1, 2, 3, 4, 5, 6, 8, 9, 10, 12, 13, 15, 16, 17, 18, 20, 21, 22]`
- II категория: 18 требований `[1, 2, 3, 4, 5, 6, 8, 9, 10, 12, 13, 15, 16, 17, 18, 19, 21, 22]`
- IV категория: 8 требований `[1, 3, 4, 8, 9, 10, 21, 22]`

## Файлы для проверки

1. `backend/common/services/RequirementGeneratorService.php` - основной файл генерации
2. `backend/api/controllers/RequirementController.php` - контроллер пересчета требований
3. `Критерии_для_формирования_требований_.md` - критерии для проверки

## Что проверить и исправить

1. **Проверить метод `getNvosRequirements()`:**
   - Убедиться, что матрица категорий правильная
   - Проверить, что все требования определены в `$allRequirements`
   - Убедиться, что для III категории создаются все 16 требований

2. **Проверить метод `generateRequirements()`:**
   - Убедиться, что требования по скважине (`has_well`) добавляются
   - Убедиться, что требования по побочному продукту (`has_byproduct`) добавляются
   - Проверить фильтрацию дубликатов - возможно, она удаляет нужные требования

3. **Проверить фильтрацию для IV категории:**
   - Убедиться, что проверка `if ($categoryId == 4)` работает ТОЛЬКО для IV категории
   - Для III категории эта проверка НЕ должна блокировать требования 14, 15, 16, 17, 18

4. **Проверить удаление старых требований:**
   - В `RequirementController::actionRecalculate()` должно удаляться ВСЕ перед созданием новых
   - Убедиться, что используется транзакция и прямые SQL запросы

## Ожидаемый результат

После исправления:
- Для III категории БЕЗ дополнительных параметров: 16 требований
- Для III категории СО скважиной: 17 требований (16 + лицензия)
- Для III категории С побочным продуктом: 17 требований (16 + технические условия)
- Для III категории СО скважиной И побочным продуктом: 18 требований (16 + лицензия + технические условия)

## Инструкции

1. Прочитай файл `backend/common/services/RequirementGeneratorService.php`
2. Проверь метод `getNvosRequirements()` - убедись, что для III категории возвращаются все 16 требований
3. Проверь метод `generateRequirements()` - убедись, что дополнительные требования добавляются
4. Проверь фильтрацию дубликатов - возможно, она удаляет нужные требования
5. Добавь логирование, чтобы видеть, какие требования создаются и какие пропускаются
6. Исправь найденные проблемы
7. Проверь все категории (I, II, III, IV) на соответствие критериям

## Важно

- Матрица категорий в коде должна точно соответствовать `Критерии_для_формирования_требований_.md`
- Все требования должны быть определены в массиве `$allRequirements`
- Фильтрация для IV категории НЕ должна влиять на другие категории
- Дополнительные требования (скважина, побочный продукт) должны добавляться ПОСЛЕ базовых
