# Техническое задание: Личный кабинет клиента по экологии (MVP)

## 1. Цель

Создать веб-приложение, где по каждому клиенту автоматически строится **карта экологических требований** в зависимости от:
- категории НВОС (I–IV),
- источника водопользования (скважина / река),
- наличия побочной продукции (например, животноводство).

В личном кабинете должны:
- храниться артефакты (разрешения, отчёты, паспорта, КЭР и т.п.),
- отображаться календарь отчётности и платежей,
- показываться риски (статьи КоАП + диапазон штрафов),
- вестись договоры, счета и акты,
- быть возможность связи (чат / обратный звонок).

Для MVP достаточно блоков:
1. Карта требований  
2. Артефакты / Хранилище  
3. Календарь событий  
4. Риски  
5. Договоры / Акты  

---

## 2. Основной функционал

### Для клиента:
- Регистрация / авторизация  
- Просмотр своих требований и статусов (в работе, выполнено, не выполнено)
- Хранилище документов (с возможностью загрузки / скачивания)
- Возможность загрузки с аудитом (доп. плата)
- Календарь с датами экологической отчётности
- Общение через чат / заказ обратного звонка

### Для сотрудников:
- Создание клиента и заполнение анкеты
- Автоматическое формирование требований на основе анкеты и категории
- Изменение статусов требований и договоров
- Динамический календарь (после сдачи отчёта ставится новая дата)

---

## 3. Роли и доступы

- **Админ:** полный доступ ко всем клиентам.  
- **Менеджер:** доступ только к своим клиентам.  
- **Специалист:** доступ к своим проектам.  
- **Клиент:** доступ только к своим данным.

Авторизация — email + пароль (SSO опционально).  
В БД использовать RLS (Row-Level Security) по client_id / site_id.

---

## 4. Интеграции

- API-интеграция с учётной системой (например, Bubble) для статусов договоров, счетов, актов.  
- Возможность подключения источников данных в будущем.

---

## 5. Безопасность

- Соответствие 152-ФЗ (персональные данные, доступы по ролям, аудит).  
- RLS для всех таблиц.  
- Логирование действий (загрузка / удаление файлов, смена статусов).  
- Ежедневное резервное копирование БД и Storage (≥30 дней хранения).

---

## 6. Админ-панель

- Справочники НПА (код, название, ссылка, блок)
- Правила построения требований
- Управление пользователями и ролями
- Возможность ручного редактирования требований

---

### Водопользование
- Если **скважина** → требуется **Лицензия на пользование недрами**
- Если **река / озеро** → требуется **Решение на водопользование** и/или **Договор водопользования**

---

### Побочная продукция
- Если есть побочный продукт (например, животноводство) → добавить требование  
  **«Технические условия “Удобрения органические на основе побочной продукции животноводства”»**

---

### Обучение ответственных лиц
- Требуется наличие удостоверения о прохождении обучения

---

## 8. Итог
MVP должен содержать:
- автоматическое формирование карты требований по критериям (категория, водопользование, побочная продукция);
- CRUD по клиентам, документам, договорам и событиям;
- хранение артефактов;
- календарь отчётности;
- динамические статусы и роли;
- безопасную архитектуру и чистый UI.
