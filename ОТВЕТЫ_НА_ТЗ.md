## 3. Структура базы данных

### Основные таблицы:

1. **users** - Пользователи системы
   - id, name, email, password_hash, role, client_id, auth_key, created_at, updated_at
   - Роли: admin, manager, specialist, client

2. **categories** - Категории НВОС
   - id, title, description
   - I, II, III, IV категории

3. **clients** - Клиенты (компании)
   - id, name, category_id, has_well, has_river, has_byproduct, responsible_person, created_at, updated_at

4. **requirements** - Экологические требования
   - id, client_id, title, status, deadline, basis, artifacts, document_year, responsible_person, created_at, updated_at
   - Статусы: pending, in_progress, completed, not_completed

5. **documents** - Документы клиентов
   - id, client_id, file_path, type, status, created_at, updated_at

6. **contracts** - Договоры и акты
   - id, client_id, number, status, date, created_at, updated_at

7. **events** - События календаря
   - id, client_id, title, date, completed, created_at, updated_at

8. **risks** - Риски по КоАП
   - id, requirement_id, article, fine_min, fine_max

9. **npa** - Справочник нормативно-правовых актов
   - id, code, title, link, block, created_at, updated_at

10. **audit_log** - Лог действий пользователей
    - id, user_id, entity_type, entity_id, action, timestamp

### Связи между таблицами:
- users.client_id → clients.id (FK, nullable)
- clients.category_id → categories.id (FK)
- requirements.client_id → clients.id (FK)
- documents.client_id → clients.id (FK)
- contracts.client_id → clients.id (FK)
- events.client_id → clients.id (FK)
- risks.requirement_id → requirements.id (FK)
- audit_log.user_id → users.id (FK)

### Почему такая структура:
- Нормализация данных (3NF)
- Разделение ответственности (users отдельно от clients)
- Гибкость для расширения (добавление новых типов документов, событий)
- Аудит действий пользователей
- Связи через внешние ключи для целостности данных

**Подробная ER-диаграмма:** см. `docs/ER-diagram.md`

## 4. Развертывание проекта

**Локально (Docker Compose):**
```bash
docker-compose up -d
docker-compose exec backend php yii migrate
docker-compose exec backend php yii seed
```

**Доступ:**
- Frontend: http://localhost:3000
- Backend API: http://localhost:8080
- Adminer (БД): http://localhost:8081

**Для продакшена:**
- Настроены Dockerfile для production
- Переменные окружения через .env
- Готово к деплою на любой хостинг с поддержкой Docker

**Инструкции по развертыванию:** см. `README.md` и `docs/setup_guide.md`
